## CSS variables

All colors, fonts, and sizes use `--afw-*` variables:

```css
.afw, .afw-prose {
  --afw-accent: #e11d48;
  --afw-font-content: Georgia, serif;
  --afw-content-size: 1.25rem;
  --afw-quote-style: italic; /* italic quotes (default: normal) */
}
```

## Dark theme

```html
<div data-afw-theme="dark" x-data="wysiwyg()"></div>
<article class="afw-prose" data-afw-theme="auto">…</article>
```

`"auto"` follows the system setting (`prefers-color-scheme`).

A `.dark` class on an ancestor (usually `<html>`, as in Tailwind, Flux, and Nuxt UI) also switches the editor and `.afw-prose` to dark immediately, without a reload. To stay light inside `.dark`, set `data-afw-theme="light"`.

::note
If `.afw-prose` has `x-ignore`, Alpine bindings on that element itself (e.g. `:data-afw-theme`) don't run either. Write the attribute directly or set it with JavaScript.
::

## Output typography

The `afw-prose` class applies the same typography as the editor:

```blade
<article class="afw-prose">{!! $post->body !!}</article>
```

Full-size media in `.afw-prose` extends outward by `--afw-prose-bleed` (default `0`).

## No clashes with frameworks

All classes use the `afw-` prefix, `--afw-*` variables, and `data-afw-*` attributes. Editor styles are written explicitly so they aren't affected by Bootstrap 5 or Tailwind resets; this is covered by automated tests.

## Language

The UI is in English by default. Use `lang: 'id'` for Indonesian, and `strings` to override individual labels:

```js
wysiwyg({ lang: 'id' })
wysiwyg({ strings: { placeholder: 'Write your story…', bold: 'Strong' } })
```

## Custom layout

Provide a `data-afw-editor` element inside the component; the built-in UI markup won't be injected and you're free to build your own toolbar:

```html
<div x-data="wysiwyg({ name: 'body' })">
  <div class="my-toolbar">
    <button type="button" @mousedown.prevent @click="exec('bold')" :class="{ active: isActive('bold') }">B</button>
  </div>
  <div data-afw-editor x-ignore></div>
</div>
```
