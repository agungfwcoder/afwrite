## Adding images

- Type `/image` (or the Indonesian `/gambar`), or click `+` and choose **Image**
- Drag an image file into the editor
- Paste a screenshot or a copied image

Accepted formats: PNG, JPG, GIF, WebP, AVIF. While uploading, a preview appears immediately with a progress indicator.

## Upload to a server

Without the `upload` option, images are stored as **base64** inside the HTML. For production, provide a function that sends the file and returns a URL:

```js
async function uploadImage(file) {
  const body = new FormData()
  body.append('image', file)
  const res = await fetch('/upload', { method: 'POST', body })
  if (!res.ok) throw new Error('Upload failed')
  return (await res.json()).url
}
```

```html
<div x-data="wysiwyg({ name: 'body', upload: uploadImage, maxImageSize: 2 * 1024 * 1024 })"></div>
```

The upload function may also return an object. `mediaId` (the ID in your app's media library, numeric only) is stored on the image:

```js
upload: async (file) => {
  // ...send the file...
  return { url: '/storage/a.jpg', mediaId: 42, alt: '' } // alt is optional
}
```

```html
<figure><img src="/storage/a.jpg" alt="" data-media-id="42"><figcaption>Figure 1</figcaption></figure>
```

The value is also available as `getMeta().image.mediaId`, e.g. to use an image from the article body as the feature image. Non-numeric values are dropped.

If the upload fails or the file is too large, the image is cancelled and a message appears in a toast (the `wysiwyg-error` event). For Laravel, an upload controller is provided in [Laravel integration](/integrations/laravel).

## Choosing from your app's gallery

By default the `image` command opens the device file dialog. With `imageRequest: true` it fires the
`wysiwyg-image-request` event instead, so your app can show its own media picker (a CMS gallery
modal, for example). The event `detail` has three functions, and each one works only once, so a
double click in the gallery can't insert two images:

| Function | Description |
|---|---|
| `insert(images)` | Insert at the cursor position from when the request started. Takes `{ src, alt?, mediaId?, size? }`, an array of them, or a `FileList` |
| `pickFiles()` | Open the device file dialog instead (for an "Upload from device" button in your picker) |
| `cancel()` | Return the cursor to the editor without inserting anything |

```html
<div x-data="wysiwyg({ name: 'body', imageRequest: true, upload: uploadImage })"
     @wysiwyg-image-request="openGallery($event.detail)"></div>
```

```js
let request = null // keep it outside Alpine's reactive data
function openGallery(detail) {
  request = detail
  galleryModal.show()
}
galleryModal.onSelect = (media) => request.insert({ src: media.url, mediaId: media.id })
galleryModal.onClose = () => request?.cancel()
```

`src` follows the same rules as pasted HTML (`http(s)`, `//`, relative paths, and raster `data:`
images when `allowDataImages` is on). An invalid `src` is skipped with a `wysiwyg-error`. A
non-numeric `mediaId` is dropped. Drag & drop and pasted files still go through `upload`.

## Replacing an image

Click an image and choose **Replace image** in the media toolbar. The new image takes the old one's
place: the caption, position, and size stay, and it is a single undo step. The alt text and
`mediaId` come from the new image (the old alt described the old picture), so the alt button shows
right away when it still needs filling in.

Without `imageRequest`, the button opens the file dialog (one file, uploaded through `upload`). With
`imageRequest: true`, the same `wysiwyg-image-request` event fires, with two extra properties:

| Property | Description |
|---|---|
| `mode` | `'insert'` (the `image` command) or `'replace'` (the **Replace image** button) |
| `current` | Only with `'replace'`: `{ src, alt, mediaId }` of the image being replaced, e.g. to highlight it in your gallery |

In `'replace'` mode, `insert(image)` replaces the selected image instead of inserting a new one, and
`pickFiles()` replaces it with the chosen file. The gallery code above works unchanged; only the
modal title needs to look at `mode`:

```js
function openGallery(detail) {
  request = detail
  galleryModal.title = detail.mode === 'replace' ? 'Replace image' : 'Insert image'
  galleryModal.highlight(detail.current?.mediaId)
  galleryModal.show()
}
```

If the image was removed while the modal was open, `insert()` does nothing. If an upload for the
replacement fails, the old image comes back and `wysiwyg-error` fires.

## Editing images

Click an image to show the media toolbar:

| Button | Function |
|---|---|
| Normal size / Wide / Full width | Display size (`data-size="wide"` / `"full"`) |
| Replace image | Swap in another image, keeping caption, size, and position (see [Replacing an image](#replacing-an-image)) |
| Alt text | Description for screen readers |
| Remove media | Removes the image (also Backspace/Delete) |

Type the caption directly below the image.

## Video

Type `/video` and paste a link, or **paste a YouTube/Vimeo link on an empty line**. YouTube videos use the `youtube-nocookie.com` domain, and the iframe URL is always rebuilt from the video ID, never from the raw URL.

## Divider

Type `--- ` or `/divider` (or the Indonesian `/pemisah`). Click the empty gap around a divider or image to add a new line there.

## API

```js
editor.insertImages(files)       // File[] or FileList
editor.exec('image', { src: '/storage/a.jpg', mediaId: 12 }) // from a URL; also an array
editor.selectedMedia()           // { kind: 'image' | 'embed' | 'divider', size, alt, src, mediaId } or null
editor.replaceMedia({ src: '/storage/b.jpg', mediaId: 13 }) // replace the selected image; or a File
editor.exec('replaceImage')      // no argument: gallery (imageRequest) or file dialog
editor.setMediaSize('wide')      // the currently selected media
editor.setMediaAlt('Mountain view')
editor.removeMedia()
```
