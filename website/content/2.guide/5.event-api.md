## Alpine events

Dispatched from the editor element and they *bubble*, so you can catch them on a parent element:

```html
<div x-data="wysiwyg()" @wysiwyg-change="body = $event.detail.html"></div>
```

| Event | `detail` |
|---|---|
| `wysiwyg-ready` | `{ editor }` |
| `wysiwyg-change` | `{ html, meta }`, where `meta` is the result of `getMeta()` |
| `wysiwyg-focus` / `wysiwyg-blur` | |
| `wysiwyg-error` | `{ message, error? }` |
| `wysiwyg-image-request` | `{ insert, pickFiles, cancel }`, only with `imageRequest: true` (see [Images & video](/guide/images-video#choosing-from-your-apps-gallery)) |

## Title & slug

The `wysiwyg-change` event carries `meta`, so the title and slug are available right away, e.g. for a URL preview:

```html
<form method="post" x-data="{ slug: '', edited: false }"
      @wysiwyg-change="if (!edited) slug = $event.detail.meta.slug">
  <input name="slug" x-model="slug" @input="edited = true">
  <div x-data="wysiwyg({ name: 'body', title: true, titleName: 'title' })"></div>
</form>
```

`slugify()` can also be used on its own:

```js
import { slugify } from 'afwrite'   // CDN: window.Afwrite.slugify

slugify('Café au lait, please!')    // 'cafe-au-lait-please'
slugify('A long title…', { maxLength: 60 })
```

::caution
A slug from the browser is only a **preview**. Non-Latin scripts (Arabic, Chinese, …) produce an empty slug, and uniqueness can only be checked on the server. Generate the final slug on the server; see [Laravel integration](/integrations/laravel#title-slug-article-mode).
::

## Alpine component methods

Call them from markup inside the component, or via `Alpine.$data(el)`:

| Method | Description |
|---|---|
| `getHTML()` / `setHTML(html)` | Get / replace the content (always sanitized) |
| `getJSON()` / `setJSON(doc)` | Content as ProseMirror document JSON |
| `getMeta()` | Medium-style preview: `{ image, title, subtitle, slug }` from the first image, first text, and second text |
| `exec(command, ...args)` | Run a command |
| `insertImage(images)` | Insert images that already have a URL: `{ src, alt?, mediaId?, size? }` or an array of them |
| `isActive(command)` | Whether a format is active at the cursor |
| `setReadOnly(bool)` | Toggle read-only mode |
| `focus()` | Focus the end of the editor |
| `editor()` | The `Editor` instance |

## `Editor` API

| Method | Description |
|---|---|
| `exec(name, ...args)`, `isActive(name)`, `state()`, `formatValues()` | Commands & format state (`formatValues()`: `{ color, highlight, align }` at the cursor) |
| `getHTML()`, `setHTML(html, { resetHistory })`, `getJSON()`, `setJSON(doc)`, `getText()`, `clear()`, `isEmpty()` | Content |
| `normalizeHTML(html)` | The HTML that `getHTML()` would return after `setHTML(html)`, without changing the content; for comparing external content |
| `insertHTML(html)`, `insertText(text)`, `paste({ html, text, files })`, `insertImages(files \| images)` | Insert |
| `undo()`, `redo()`, `canUndo()`, `canRedo()` | History |
| `restoreDraft()`, `discardDraft()`, `clearDraft()`, `draft` | Autosave |
| `setReadOnly(bool)`, `focus()`, `stats()` | Other |
| `on(event, fn)` → returns an unsubscribe function, `off()`, `destroy()` | Events |

`Editor` events: `change`, `state`, `selection`, `slash`, `history`, `readonly`, `linkrequest`, `embedrequest`, `imagerequest`, `error`, `focus`, `blur`. `imagerequest` fires only while it has a listener; without one, the `image` command opens the file dialog.

```js
const editor = Alpine.$data(el).editor()
const stop = editor.on('change', (html) => console.log(html))
editor.paste({ html: '<p>Hello <b>world</b></p>' }) // same rules as a real paste
stop()
```

## Tiptap access

The Tiptap instance is available as `editor.tiptap` for advanced use:

```js
editor.tiptap.commands.selectAll()
editor.tiptap.state.doc.childCount
```

::note
Changes made through `editor.tiptap` still fire the `change` event, but the output is still limited by the sanitization whitelist.
::

## Without Alpine

The editor core can be used on its own, without the floating UI (links and videos use the browser's built-in `prompt()`):

```js
import { Editor } from 'afwrite'
import 'afwrite/style.css'

const editor = new Editor(document.querySelector('#editor'))
editor.on('change', (html) => (input.value = html))
document.querySelector('#bold').onclick = () => editor.exec('bold')
```

The `#editor` element must be wrapped in an element with the `afw` class for the styles to apply.
