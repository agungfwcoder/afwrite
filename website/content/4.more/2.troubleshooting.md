## The editor doesn't appear

**Check the script order (CDN).** `afwrite.min.js` must load **before** Alpine, and both need `defer`:

```html
<script defer src="https://cdn.jsdelivr.net/gh/agungfwcoder/afwrite@2/dist/afwrite.min.js"></script>
<script defer src="https://cdn.jsdelivr.net/npm/alpinejs@3/dist/cdn.min.js"></script>
```

**Check the plugin registration (bundler).** `Alpine.plugin(afwrite)` must run before `Alpine.start()`.

**Look in the browser console.** `wysiwyg is not defined` means the plugin wasn't registered before Alpine started.

## Two Alpine instances (Livewire)

Livewire already ships and starts its own Alpine. If you also `import Alpine from 'alpinejs'` or call `Alpine.start()`, the two instances conflict: components initialize twice or not at all. With Livewire, only `import './wyswyg'`. See [Livewire](/integrations/livewire#install).

## The editor has no styling

- Load `afwrite.css` (CDN) or `import 'afwrite/style.css'` (bundler).
- Load the CSS in `<head>`, not at the end of `<body>`.
- When using the [`Editor` class without Alpine](/guide/event-api#without-alpine), wrap the editor element in an element with the `afw` class.

## Raw content flashes before the editor loads

The component hides itself until Alpine has set it up, but that only works if the CSS has already loaded. Put the stylesheet in `<head>`. In Laravel, `@vite` does this in production builds; in development a short flash can still happen.

## Saved content looks different on the public page

Wrap it in `afw-prose`:

```blade
<article class="afw-prose">{!! $post->body !!}</article>
```

If the page uses a dark theme, add `data-afw-theme="auto"` or rely on a `.dark` class on `<html>`. Note that `x-ignore` on `.afw-prose` also disables Alpine bindings on that element itself.

## Image uploads fail

The editor cancels the image and shows the error in a toast (the `wysiwyg-error` event). Check the response in the browser's network tab:

| Status | Likely cause |
|---|---|
| `419` | Missing CSRF token (Laravel). Add `<meta name="csrf-token" content="{{ csrf_token() }}">` to the layout. |
| `401` / `302` to login | The upload route uses `auth` middleware and the user isn't logged in. |
| `413` | The web server rejects the size before Laravel sees it. Raise `client_max_body_size` (nginx) or `upload_max_filesize` and `post_max_size` (PHP). |
| `422` | Validation failed: wrong format (SVG isn't allowed) or larger than the controller's `max:5120` (5 MB). |
| `500` | Usually storage: run `php artisan storage:link` and check that `storage/` is writable. |

Your upload function must **return the URL** (or `{ url, mediaId? }`) and **throw** on failure. If it returns nothing, the upload is treated as failed and the image is removed.

### Images upload but don't show

The returned URL isn't reachable from the browser. With Laravel's `public` disk, run `php artisan storage:link` and check that `APP_URL` matches the address you use.

### "Image too large"

The editor rejects files above `maxImageSize` (default 5 MB) before uploading. Raise it with `maxImageSize`, or set `0` for no limit, and raise the server limit to match.

## Formatting is lost after saving

Your server sanitizer is stricter than the editor whitelist. With Laravel, use the provided `WyswygHtml::clean()`: it accepts all editor output, including colors, highlights, alignment, and `data-media-id`. If you use [custom extensions](/guide/security#custom-extensions), add their tags and attributes to both the `sanitize` option and the server whitelist.

## `x-model` doesn't update

Put `x-modelable="html"` on the editor element together with `x-model`:

```html
<div x-data="wysiwyg()" x-modelable="html" x-model="body"></div>
```

With Livewire, the value is sent with the next action (e.g. `save`), not on every keystroke. That is expected.

## The editor resets or loses the cursor (Livewire)

Wrap the editor in `wire:ignore` so Livewire doesn't replace its DOM when the component re-renders:

```blade
<div wire:ignore>
    <div x-data="wysiwyg()" x-modelable="html" x-model="$wire.body"></div>
</div>
```

## Autosave doesn't restore anything

- localStorage is unavailable (private browsing, blocked site data, quota exceeded). Autosave turns itself off without errors in that case.
- The draft is identical to the current content, so there is nothing to restore.
- The draft was cleared when the form was submitted.
- Two editors share the same key. Use a unique key per document, e.g. `post-{{ $post->id }}`.

## A slug comes out empty

`slugify()` only handles Latin text; titles in Arabic, Chinese, and other scripts produce an empty slug. Treat the browser slug as a preview and generate the final slug on the server, with a fallback. See [Title & slug](/integrations/laravel#title-slug-article-mode).
