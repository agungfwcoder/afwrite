## 2.0.0 [2026-10-20]{.ch-date} [Latest]{.ch-latest}

::div{.ch-card .ch-intro}
New engine: [Tiptap](https://tiptap.dev) 3 / [ProseMirror](https://prosemirror.net), replacing
`contenteditable` + `document.execCommand`. The look, Alpine component, `Editor` API, events, and
HTML output format are unchanged, so v1 content still loads.

Until there are users, further small changes are folded into this 2.0.0 release. The `@2` CDN and
`npm install github:agungfwcoder/afwrite#semver:^2` always fetch the latest v2.
::

### [Changed]{.ch-chip .ch-changed}
- `alpinejs` is now an optional peer dependency
- The default UI language is now English (`lang: 'en'`), including the Laravel Blade component.
  Use `lang: 'id'` (or `lang="id"` in Blade) for Indonesian
- Typing, lists, formatting, and cursor behavior are handled by ProseMirror: identical across
  browsers, with no Chrome/Safari-specific patches
- JSON uses the ProseMirror document format (`{ type: 'doc', content: [...] }`); the v1 format
  (`blocks` + `marks` ranges) is no longer supported
- The package is now named `afwrite` (previously `wyswyg`, a name already taken on npm by another
  package): `import afwrite from 'afwrite'`, `import 'afwrite/style.css'`. Build files are now
  `dist/afwrite.js` & `dist/afwrite.css`. The `x-data="wysiwyg(...)"` component, events, and names in
  the Laravel integration (`WyswygHtml`, the `wyswyg.upload` route) are unchanged
- `dist/` is committed to the repo so it can be installed from GitHub and loaded via CDN
- Build: ES module `dist/afwrite.js` (Tiptap/ProseMirror as dependencies, about 135 KB gzip in an
  app) and a standalone build for CDN (see below). The v1 UMD build was removed
- The built-in toolbar & bubble now include underline, strikethrough (toolbar only), text color &
  highlight, and alignment buttons (see New). Article mode (`title: true`) stays as before
- JSON: `paragraph` & `heading` nodes carry `attrs.textAlign` (`null` = left-aligned), `image` nodes
  carry `attrs.mediaId`
- Note on existing content: `<strong>`/`<em>` are read, but the editor always writes `<b>`/`<i>`. Old
  content that is opened and saved again will have its tags changed (the content is the same)

### [New]{.ch-chip .ch-new}
- **Without Alpine**: `create(el, options)` (CDN: `Afwrite.create`) gives the full UI (toolbar,
  bubble, slash menu, `+` button, media toolbar, palette, drag handle) in plain JavaScript. Same
  options as `wysiwyg({...})`; events via `on('change', fn)` and the `wysiwyg-*` DOM events;
  `destroy()` restores the element. The Alpine component is now a thin adapter on top, used exactly
  as before. See [JavaScript (no Alpine)](/integrations/javascript)
- React & Vue wrappers in `examples/` (tested from separate Vite apps, including React StrictMode)
  and docs pages for [React](/integrations/react) and [Vue](/integrations/vue)
- The editor UI and content get `x-ignore` automatically, so `create()` is safe on Alpine pages
- Standalone build `dist/afwrite.min.js` for `<script>` / CDN (jsDelivr), with Tiptap/ProseMirror
  bundled. The plugin registers itself automatically; the API is at `window.Afwrite`
- `headings` option (default `[2, 3]`): H2–H6 heading levels. Toolbar & bubble buttons (bubble shows
  at most 2 levels), slash menu, Ctrl/⌘+Alt+2…6 shortcuts, and `##`…`######` markdown follow the
  active levels; other levels are demoted to the nearest active level. Blade prop `:headings`, and
  `WyswygHtml::clean()` now allows h2–h6
- `toJSON(html, options)` / `fromJSON(doc, options)` accept `headings`
- H4, H5, H6 icons and a `withHeadings()` helper for building your own toolbar
- With exactly two heading levels active (including the default), their buttons show as a large **T**
  and a small **t**, like Medium; three or more levels stay H2/H3/…
- `title` option (Medium-style article mode): the first line is always an `<h1>` title (plain text),
  with a placeholder and "Title/Subtitle" labels in the left margin when the editor is wide enough
  and the block has content. The small heading button on the line right after the title creates a
  subtitle `<p class="afw-subtitle">` (text + links); elsewhere it remains a regular section heading.
  Formats that don't apply are shown dimmed. Pasting multiple lines into the title: the first line
  becomes the title, the rest becomes body. Blade prop `:title`, and `WyswygHtml::clean()` allows
  `h1` & the `afw-subtitle` class
- Article mode: images, videos, and dividers may sit above the title (the first text is still the
  title). The `+` button or `/` on an empty title (menu with Image/Video/Divider), or pasting/dragging
  an image onto the title, inserts it right above the title; the cursor stays in the title
- `getMeta()`: `{ image, title, subtitle }` from the first image, first text, and second text, like a
  Medium story preview
- Moving blocks: a ⋮⋮ handle appears to the left of a block on hover (sharing a slot with the `+`
  button, which is now 24px). Drag to move (drop indicator & a single undo step), click to select the
  whole block. Ctrl/⌘+Shift+↑/↓ moves blocks via the keyboard. The article title/subtitle doesn't
  move. `dragHandle: false` option to disable the handle. API `moveBlock()`, `selectBlock()`
- `slugify(text, { maxLength })`: a URL slug from a title ("Café Pagi!" -> `cafe-pagi`). Preview
  only; the final slug is still generated by the server
- `getMeta()` also returns `slug`, and the `wysiwyg-change` event now carries `{ html, meta }`
- `titleName` option: a hidden input containing the title (article `<h1>` / first text). Blade prop
  `title-name`
- `editor.tiptap`: access to the Tiptap instance for advanced use
- Gap cursor (cursor between two media blocks) and a drop indicator when dragging images
- Additional formats, `formats` option (all by default; not available in article mode, which stays
  plain like Medium): underline `<u>` (Ctrl/⌘+U), strikethrough `<s>` (Ctrl/⌘+Shift+X), text color
  `<span style="color: #…">` and highlight `<mark style="background-color: #…">` from a palette
  (`colors`, `highlights` options), and paragraph & heading alignment
  `class="afw-align-center|right|justify"` (Ctrl/⌘+Shift+L/E/R/J). Colors are always written as hex
  for a stable round-trip; colors outside the palette are dropped. Old content with `ql-align-*`
  (Quill), `style="text-align"`, `<strike>`, `<del>`, `<ins>`, `<font color>`, and
  `<mark data-color>` is also read. Commands `underline`, `strike`, `color`, `highlight`, `align`,
  `alignLeft/Center/Right/Justify`; `withFormats()` helper. Blade prop `:formats`, and
  `WyswygHtml::clean()` allows all of them
- `data-media-id` on images (the app's media library ID, digits only): `upload(file)` may return
  `{ url, mediaId, alt }`; the value is also exposed as `getMeta().image.mediaId`.
  `window.wyswygUpload(url, { field })` reads `mediaId` from the JSON response
- `extensions` option (additional Tiptap extensions) and `sanitize: { allowTags, allowAttributes,
  allowClasses }` for app-specific nodes/marks without forking
- Dark mode follows a `.dark` class on an ancestor (Tailwind, Flux, Nuxt UI) without a reload;
  `data-afw-theme="light"` to stay light
- `editor.normalizeHTML(html)` and `editor.formatValues()`
- Images from your app's gallery: with `imageRequest: true`, the `image` command (button, `/image`)
  fires a `wysiwyg-image-request` event with `{ insert, pickFiles, cancel }` instead of opening the
  file dialog, so your app can show its own media picker. The selection is saved when the event
  fires, and each function works only once. `exec('image', { src, alt?, mediaId?, size? })` (or an
  array) and the `insertImage()` method insert images from a URL in one undo step; `src` is
  validated like pasted HTML. Core event `imagerequest`, strings `blocks.imageRequest` and
  `errorImageSrc`. Drag & drop and pasted files still go through `upload`
- Replace an existing image: a **Replace image** button in the media toolbar, the `replaceImage`
  command, `editor.replaceMedia(descriptor | File)`, and the `replaceImage()` method. Caption,
  position, and size stay, in one undo step; alt and `mediaId` follow the new image. With
  `imageRequest`, `wysiwyg-image-request` carries `mode: 'replace'` and
  `current: { src, alt, mediaId }` (the `image` command uses `mode: 'insert'`). A failed upload
  brings the old image back. `selectedMedia()` now also returns `src` and `mediaId`

### [Fixed]{.ch-chip .ch-fix}
- Mobile: when the virtual keyboard is open, the format bubble pins just above the keyboard (no
  longer hidden behind it or fighting the OS Cut/Copy menu); the selection scrolls to stay visible.
  Floating elements are measured against `visualViewport`
- x-model / `$wire`: external HTML with the same content but different markup (e.g. the output of
  `WyswygHtml::clean()` after saving) no longer reloads the editor, so the cursor doesn't jump and
  undo history is kept
- Laravel integration: `resources/js/wyswyg.js` no longer imports and starts its own Alpine
  (which clashed with Livewire's bundled Alpine). Tested with Laravel 13 + Livewire 4: `$wire`
  x-model, saving, reloading, and repeated `wire:navigate` with no leftover listeners/instances
- A selection set by a script, or a button pressed very quickly after Shift+Arrow, is now always
  picked up before the command runs
- Dropping external HTML/text uses the same rules as paste in all browsers

## 1.0.0 [2026-10-17 · First release]{.ch-date}

::div{.ch-card}
[Phase 5 · API & stability]{.ch-label}

- Undo/redo with its own history (consecutive typing is merged; media operations are recorded),
  undo/redo toolbar buttons, and support for the browser's Edit menu
- Read-only mode (`readonly`, `setReadOnly()`)
- `x-model` support via `x-modelable="html"`, `wysiwyg-ready/focus/blur/error` events
- Indonesian & English (`lang`, `strings`)
- `.afw-prose` class for displaying output with the same typography
- Accessibility: toolbar navigation with arrows/Home/End, `aria-activedescendant` in the slash menu
- `editor.paste({ html, text, files })` API
- Safari fixes: cursor position after creating a list, turning a list off, typing after a markdown
  shortcut, spaces when pasting
- Browser tests in Chromium, Firefox, and WebKit (`npm run test:browser -- all`)
