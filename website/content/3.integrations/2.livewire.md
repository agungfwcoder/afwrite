Tested with Laravel 13 + Livewire 4: typing, saving, server-side sanitization, reloading, and navigating back and forth with `wire:navigate`.

## Install

Livewire already ships and starts its own Alpine. **Don't** import `alpinejs` or call `Alpine.start()`: two Alpine instances will conflict. Just add:

```js [resources/js/app.js]
import './wyswyg' // from integrations/laravel/resources/js/wyswyg.js
```

`wyswyg.js` loads `afwrite` along with its CSS. The plugin registers itself on the `alpine:init` event and exposes `window.wyswygUpload`.

## Component

```blade [livewire/post-editor.blade.php]
<div>
    <div wire:ignore>
        <div x-data="wysiwyg({ upload: window.wyswygUpload('{{ route('wyswyg.upload') }}') })"
             x-modelable="html" x-model="$wire.body"></div>
    </div>

    <button wire:click="save">Save</button>
</div>
```

```php [app/Livewire/PostEditor.php]
use App\Support\WyswygHtml;

public string $body = '';

public function save(): void
{
    $this->body = WyswygHtml::clean($this->body);
    $this->post->update(['body' => $this->body]);
}
```

- `wire:ignore` stops Livewire from touching the editor's DOM when the component re-renders.
- `x-modelable="html"` + `x-model="$wire.body"` syncs the editor content with the `$body` property. The value is sent with the next action (e.g. `save`), not on every keystroke. `$wire.entangle('body')` works too.
- After `save`, `$body` holds HTMLPurifier output, which is written slightly differently (e.g. `color:#e11d48;`). The editor compares content after normalization, so it doesn't reload and the cursor doesn't jump.
- You can also sync on submit without `x-model`: `Alpine.$data(el).getHTML()`.

## `wire:navigate`

The editor is cleaned up automatically (`destroy()`) when you leave the page. Navigating back and forth leaves no stray listeners or duplicate instances.
