`create()` gives you the same editor as the Alpine component (toolbar, bubble, slash menu, `+` button, media toolbar, color palette, drag handle) with no Alpine on the page. It is also what the [React](/integrations/react) and [Vue](/integrations/vue) wrappers are built on.

## Install

::code-group

```html [CDN]
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/agungfwcoder/afwrite@2/dist/afwrite.css">
<script src="https://cdn.jsdelivr.net/gh/agungfwcoder/afwrite@2/dist/afwrite.min.js"></script>
```

```bash [npm]
npm install github:agungfwcoder/afwrite#semver:^2
```

::

## Create an editor

```html
<form method="post">
  <div id="body"><p>Initial content (optional)</p></div>
  <button>Save</button>
</form>

<script>
  // Bundler: import { create } from 'afwrite'; import 'afwrite/style.css'
  const editor = Afwrite.create('#body', { name: 'body', upload: uploadImage })
  editor.on('change', ({ html }) => console.log(html))
</script>
```

The options are the same as for `wysiwyg({...})`; see [Options](/guide/options). The element's children become the initial content, and `name` adds an `<input type="hidden">` that is submitted with the form.

::tip
`create()` runs synchronously. Call it right after the element (or on `DOMContentLoaded`) so the raw initial content isn't visible for long before the editor takes over.
::

## Instance API

| Method | Description |
|---|---|
| `getHTML()` / `setHTML(html)` | Get / replace the content (always sanitized) |
| `getJSON()` / `setJSON(doc)` | Content as ProseMirror document JSON |
| `getMeta()` | `{ image, title, subtitle, slug }` from the content |
| `exec(command, ...args)` | Run a [command](/guide/commands) |
| `isActive(command)` | Whether a format is active at the cursor |
| `insertImage(images)` / `replaceImage(image?)` | Insert images that already have a URL / replace the selected image |
| `setReadOnly(bool)`, `focus()` | Read-only mode, focus the end of the editor |
| `restoreDraft()` / `discardDraft()` | Answer the [autosave](/guide/autosave) draft banner |
| `on(event, fn)` → unsubscribe function, `off(event, fn)` | Events (below) |
| `destroy()` | Remove the editor and restore the element's original content |
| `editor` | The [`Editor`](/guide/event-api#editor-api) instance, for advanced use |

## Events

```js
editor.on('change', ({ html, meta }) => save(html))
editor.on('error', ({ message }) => notify(message))
```

| Event | Payload |
|---|---|
| `ready` | `{ editor }` (fires after `create()` returns, so listeners added right away still get it) |
| `change` | `{ html, meta }` |
| `focus` / `blur` | |
| `error` | `{ message, error? }` |
| `image-request` | `{ mode, current?, insert, pickFiles, cancel }`, only with `imageRequest: true` |

The same events are also dispatched as DOM events (`wysiwyg-change`, `wysiwyg-ready`, …) that bubble from the editor element, exactly as with Alpine.

## Removing and re-creating

`destroy()` removes listeners, destroys the editor, and puts the element back the way it was before `create()`, so it can be created again (this is what makes React StrictMode work). Calling `create()` twice on the same element returns the existing instance.

## Your own toolbar

Put an element with `data-afw-editor` inside; the built-in UI is then not injected and you call the API from your own buttons:

```html
<div id="body">
  <button type="button" id="bold">B</button>
  <div data-afw-editor><p>Initial content</p></div>
</div>

<script>
  const editor = Afwrite.create('#body')
  const bold = document.getElementById('bold')
  bold.addEventListener('mousedown', (e) => e.preventDefault()) // keep focus in the editor
  bold.addEventListener('click', () => editor.exec('bold'))
  editor.editor.on('state', () => bold.classList.toggle('active', editor.isActive('bold')))
</script>
```

## On a page that already uses Alpine

`create()` works next to Alpine and inside `x-data` components. The editor UI and content get `x-ignore` automatically, so Alpine never processes them, and Alpine attributes in stored or pasted content (`x-init`, `@click`, …) are removed by the sanitizer. On an Alpine page, `x-data="wysiwyg()"` is usually simpler, since `x-model` and cleanup come built in.
