## Inside a form

```html
<form method="post">
  <div x-data="wysiwyg({ name: 'body', upload: uploadImage })">
    <p>Initial content (optional)</p>
  </div>
  <button>Save</button>
</form>
```

The UI markup (toolbar, bubble, menus) is generated automatically. The element's children become the initial content, and `name` creates an `<input type="hidden">` holding the HTML, which is submitted with the form.

## With x-model

```html
<div x-data="{ body: '' }">
  <div x-data="wysiwyg()" x-modelable="html" x-model="body"></div>
  <p x-text="body.length + ' characters'"></p>
</div>
```

## Without Alpine

```js
const editor = Afwrite.create('#body', { name: 'body' }) // bundler: import { create } from 'afwrite'
editor.on('change', ({ html }) => console.log(html))
```

See [JavaScript (no Alpine)](/integrations/javascript), [React](/integrations/react), and [Vue](/integrations/vue).

## Medium-style (no top toolbar)

```html
<div x-data="wysiwyg({ name: 'body', toolbar: false, stats: false })"></div>
```

Formatting is still available via the bubble (select text), the slash menu, the `+` button, keyboard shortcuts, and markdown.

## Rendering the output

Use the `afw-prose` class so the rendered typography matches the editor:

```blade
<article class="afw-prose">{!! $post->body !!}</article>
```

::warning
Only print raw HTML (`{!! !!}`) **after** it has been sanitized on the server. See [Security](/guide/security).
::

## Listening for changes

Events are dispatched from the editor element and *bubble*:

```html
<div x-data="wysiwyg()" @wysiwyg-change="console.log($event.detail.html)"></div>
```

See [Events & API](/guide/event-api) for the full list.
